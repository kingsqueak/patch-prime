# Patch Prime developer notes

How each part of Patch Prime is built: where the code is, how it fits together, and what to watch out for. The project's rules and build basics are in `CLAUDE.md` at the repository root; this file holds the detail for each area. Read the section for the area you work on.

## Effects

Effects: `engine/src/` `effects`, `eq`, `multiband`, `dynamics`, `denoise` form `patchprime-dsp` (plain C++, linked by the engine and the GUI, which draws curves with it). RNNoise is fetched at configure time (`cmake/RNNoise.cmake`, pinned by SHA-256; `-DPATCHPRIME_RNNOISE=OFF` builds without noise suppression). `PATCHPRIME_EFFECTS=<strip label>` opens a strip's effects window for screenshots (saved as `<file>-2.png`).

Reverb tail (Phase 9k): an effect whose `ringsOut()` is true does its own bypass: `EffectChain` keeps calling `process()` and doesn't crossfade or call `resume()`. `ReverbEffect` ramps its input to nothing over the chain's crossfade time (ahead of the pre-delay, so what's in there still goes in) and plays dry + wet × mix; after `quietSeconds` below -100 dBFS it clears its lines and sleeps, so a bypassed reverb costs nothing. Toggling is in place (`updateChain`), so the tail survives it; replacing the chain (adding an effect, say) still loses it. Reverb bus: `DeviceModel::createReverbBus`, D-Bus `CreateReverbBus(name)`, `patchprime-ctl reverb-bus`, the Devices page's Add Reverb Bus.

## Voice tools

Voice tools (Phase 9g): `engine/src/voice.{h,cpp}` in `patchprime-dsp`. `CompressorEffect` ("compressor"): `amount` drives `fromAmount()` (threshold −10…−35 dB, ratio 1…6, 5/120 ms, makeup = half the full-scale reduction) unless `advanced`; `DeviceModel::setEffectParam` copies `fromAmount` into threshold/ratio/attack/release/makeup when advanced is switched on; meters [GR, threshold in use] (the GUI's IN line). `DeEsserEffect` ("deesser"): cut through a complementary split (x − lowpass), detection and Listen through a true highpass (so loud lows don't trigger it). `ExpanderEffect` ("expander"): ratio unit `"1:"` (ParamField formats it). The GUI hides the compressor's advanced params unless `advanced`. Built-in voice chains: `PresetStore::voiceChainNames()/voiceChain()` (static, ≤ maxEffectsPerStrip, denoise only with RNNoise), D-Bus `LoadVoiceChain`, state `voiceChains`, `PresetButton.starters` (a submenu).

## Latency

Latency (Phase 9h): `Effect::latency()` (samples, main thread, whether or not it's on; the Delay effect says 0, it's deliberate): `DenoiseEffect` a frame (480 at 48 kHz, 0 when it passes through), `LimiterEffect` its lookahead (`m_length - 1`); `EffectChain::latency()` sums the enabled ones. Plugins: `Lv2Effect` reads its latency port (`lilv_plugin_get_latency_port_index`, a control output), `ClapEffect` the `clap.latency` extension, `Vst3Effect` `getLatencySamples`; the host sends `{"latency": n}` on ready and when it changes (checked on its 30 Hz tick) and sets its own filter's `SPA_PARAM_ProcessLatency` (0 while bypassed); `PluginRunner::latency(node)`. `PipeWireGraph::setFilterLatency` (pw_filter_update_params with ProcessLatency); `BusManager::ensureEffectsNode` sets it for each built-in run when the chain changes. `BusManager::latency(key)` → `{seconds (enabled total), effects {index: seconds}}`; state `latency` {key: {total ms, effects {index: ms}}}, `Devices.latency` in QML (effects window header and cards). Recordings: `RecorderTrack::lateSeconds` (skipped at the start, padded with silence at the end); `RecordingManager::source` sets it to the strip's latency unless the track is raw. Only the strip's own effects count: a mix bus's track isn't moved for the effects of the strips feeding it, since those differ path by path. The test LV2 plugin reports 64 samples (`TEST_GAIN_LATENCY`).

The clock: every node Patch Prime makes (buses, sends, effects, plugin hosts) is in node.group `patchprime` (`nodeGroup`, busmanager.h) with `patchprime.clock` (`clockProperties`, a `support.node.driver` made through `spa-node-factory`, `PipeWireGraph::createSpaNode`; priority.driver 25000, between the buses' 20000 and a chosen master's 30000), so the clock drives them all unless a master interface does. Don't let a bus drive: a null sink driving the graph runs first in the cycle, so what came into it went out one quantum late (a take's track from that bus was 1024 samples behind).

Levels: buses and sends set `state.restore-props=false`. WirePlumber saves sink volumes by node name and restores them when the node appears; that landed after `applyVolume`, whose `m_applied` then thought the fader was already set, so a recreated bus could run at an old level.

## Cue

Cue (solo Phase 4, PFL Phase 9i): while anything is cued and the cue output is online, `patchprime.cue` (`cueNodeName`, `sendProperties`, the cue output's channels) carries it: strips ──► cue node ──monitor──► the cue output's hardware, and that output's own bus is muted. The node's volume is the cue level (devices.json `cueLevelDb`). It is managed in `reconcile()` and `linkCue`, not as a send: `linkSends` would remove links into it. AFL feeds it from `stripOuts`. PFL (`cuePreFader`, the default): the fader is on a bus's monitor ports and a bus has no output ahead of it, so `linkCue` mirrors every link into the bus onto the cue node (sends, apps, pads, the hardware, an input's effects node). So PFL is after effects on hardware inputs and before them everywhere else. D-Bus `SetCueLevel`, `SetCuePreFader`; state `cueLevelDb`, `cuePreFader`; GUI `SceneBar.qml`; `patchprime-ctl cue-level|cue-mode`.

## Recording and playback

Recording: `engine/src/recording.{h,cpp}` (`SampleRing` lock-free SPSC queue, `Recorder` and `Player` on libsndfile: FLAC/WAV/MP3, a file thread each, the realtime side only queues) and `recordingmanager.{h,cpp}` (`patchprime.record.<bus>` capture streams on mix buses and routed inputs, one `patchprime.player` stream; `PipeWireGraph::addStream`; BusManager links them via `setTaps`, by `patchprime.tap.owner`). Files in `~/Music/Patch Prime`; format and player target saved in `devices.json`. Multitrack takes (Phase 9e): `RecordingManager::startTake` records the armed strips (devices.json `multitrack`, `armed`; `recordInputsRaw` decides raw/processed for hardware inputs in every recording, single or take) through one capture filter, `patchprime.record.take`, with every track's ports in order (`PipeWireGraph::addStream` capture takes up to `maxCaptureChannels`; repeated positions are named `input_<n>_FL`), so the tracks are sample-aligned by construction; `Recorder` takes `RecorderTrack`s and splits the stream into a file each on its file thread (`Take <date time>/<label>.<ext>`, mono strips mono). `BusManager::setTaps` takes `TapTrack`s (key, ports, raw) per recorder node. A take's strips appear in `recording()`; `stop(key)` on one stops the take. MIDI/hotkey target `take`; D-Bus `SetMultitrack`, `SetArmed`, `SetRecordInputsRaw`, `StartTake`, `StopTake`, state `multitrack`, `armed`, `recordInputsRaw`, `takeFolder`, Levels `take`; GUI `TakeControls.qml`; `patchprime-ctl multitrack|arm|take`. Build needs `libsndfile1-dev` (Fedora `libsndfile-devel`, Arch `libsndfile`).

## Plugins (LV2, CLAP, VST3)

Plugins (Phase 7a, LV2): an effect of type `lv2:<uri>` (params by port symbol) in the same chain as the built-ins. `splitChain` cuts a strip's chain into segments: runs of built-ins run in `patchprime.fx.<rest>[.<n>]` filters in the engine, each plugin in its own `patchprime-pluginhost` process (`pluginhost/`, the only code linking lilv; installed to libexecdir) as node `patchprime.plug.<rest>.<n>`. BusManager links the segments in series and skips ones that aren't up (crash bypass); `PluginRunner` (engine) starts/restarts hosts and talks JSON lines over stdin/stdout (host exits on stdin EOF; exit code 2 = can't load). D-Bus `GetPlugins` lists plugins without parameters (`pluginSummariesToJson`, with `paramCount`; the full list was ~30 MB with ~700 plugins and made the window take 5 s to open), and `GetPluginParams(type)` gives one plugin's, fetched and cached by the GUI's `effectInfo` when a plugin effect is shown. Effects windows are created on first open (`InsertSlots.open`), not one per strip at start. `PluginCatalog` runs `patchprime-pluginhost --scan` only when asked (Scan Plugins, D-Bus `RescanPlugins`) or when the cache (`~/.cache/patchprime/plugins.json`, `{version, scannedAt, plugins}`) is missing or another `cacheVersion` (bump it when the list's format changes); the scan prints `{"progress": {done, total, found}}` lines, then the list. `pluginHostProgram()` prefers the build tree's host (`$PATCHPRIME_PLUGINHOST` overrides). Plugin windows (7b): the host opens the plugin's X11UI itself (`pluginhost/lv2ui.{h,cpp}`, plain Xlib top-level, no suil; needs DISPLAY in the systemd user env), idles it at 30 Hz, sends control/meter values and atom events (`EventRing`); UI control changes come back as `{"param"}` and are saved via DeviceModel; the plugin's own state (`EffectSettings::state`, lilv state string, no port values) comes back as `{"state"}` on window close / every 5 s while open / `requestPluginStates()`, and is restored before activation (`--state-follows`). CLAP (7c): type `clap:<id>`, params by CLAP param id (decimal); SDK headers fetched by `cmake/Clap.cmake` (1.2.10, SHA-256 pinned; target `patchprime-clap`); `pluginhost/clap.{h,cpp}` (`ClapEffect`, `ClapWindow`, scan via `--scan-clap <file>` subprocesses since CLAP plugins must be loaded to be read); `HostedPlugin`/`PluginWindow` (`pluginhost/hostedplugin.h`) let main.cpp run either format; `X11Window` is shared. The catalog keeps each CLAP plugin's `.clap` path (`binary`). Params reach a CLAP plugin only while it processes (an unlinked node shows stale values in its window). `request_restart` (9l) is done in place by `mainThreadTick`: the audio thread stops processing (as for `stopProcessingSoon`, the sound goes by dry), then deactivate and `prepare` again, so the window and node stay; if it can't be activated again, or asks more than `restartBurst` times in a row under a second apart, `wantsRestart` sends the host to the engine for a fresh start, which counts towards `crashLimit`. Tests also use `tests/clap/testgain.c` via `PATCHPRIME_CLAP_PATH` (replaces the CLAP search path). VST3 (7d): type `vst3:<class id hex>`, params by ParamID (decimal; stepped ≤31 store the step index, others normalized 0–1); only `vst3_pluginterfaces` v3.8.0 (MIT) is fetched by `cmake/Vst3.cmake` (target `patchprime-vst3`, interface IIDs in `pluginhost/vst3iids.cpp`); host classes in `pluginhost/vst3.cpp` with `U::Implements`; bundles scanned by `--scan-vst3 <bundle>` subprocesses (4 at a time; the scan doesn't create editor views, too slow for LSP); search path replaced by `PATCHPRIME_VST3_PATH` in tests (`tests/vst3/testgain.cpp`, component = controller). A mono LV2 plugin runs once per channel; `Lv2Effect::saveState` keeps one state per instance when they differ (`{"channels": [...]}`, else lilv's text as before, which every channel restores). Exit code 3 (a host that wants a fresh start, a VST3 kReloadComponent): it sends its state first, and the engine restarts it with its window back (it counts towards `crashLimit`, so one can't loop). Tests use `tests/lv2/testgain.c` (gain, a "crash" switch, a "halve" switch kept only in its state, "halveFirst" for one channel's instance only) via `LV2_PATH`; never rely on installed plugins in tests. `tests/lv2/testgain_ui.c` and the CLAP test plugin have X11 windows that move the gain when shown; `test_buslive::pluginWindows` opens them on a private Xvfb (skips without Xvfb and xwininfo; VST3 has no test window). Build needs `liblilv-dev lv2-dev libx11-dev` (Fedora `lilv-devel lv2-devel libX11-devel`, Arch `lilv lv2 libx11`).

## Control surface (Mackie)

Control surface (Phase 8a): `AlsaMidi` (`engine/src/alsamidi.{h,cpp}`, ALSA sequencer client "Patch Prime", port "Control Surface", on the main thread via QSocketNotifier; controllers named `<client>:<port>`, reconnected on announce events) implements `MidiPort`; `MackieControl` (`mackiecontrol.{h,cpp}`) is the Mackie Control protocol over any `MidiPort` (8 strips = enabled strips in mixer order, bank/channel, fader law `mackieFaderDb`, touch suppresses motor echo, V-Pots = sends to the SELECTed bus/output, display diffs, meters from `BusManager::loudness()`, F1–F8 = scenes, host-connection challenge answered). The port id is `controlSurface` in devices.json; D-Bus `SetControlSurface`, state `controlSurface*`. `tests/test_mackie.cpp` uses a `FakePort` and a stand-in ALSA client (skips without `/dev/snd/seq`). Build needs `libasound2-dev` (Fedora `alsa-lib-devel`, Arch `alsa-lib`).

## MIDI learn

MIDI learn (Phase 8b): a second `AlsaMidi` port, "MIDI Controller", feeds `MidiMapper` (`engine/src/midimapper.{h,cpp}`); mappings are `MidiMapping`/`MidiTarget` (`midimapping.{h,cpp}`, JSON in devices.json `midiMappings`, plus `midiController`). Targets: volume, mute, cue, sendLevel, send, effectParam, effectEnabled, record, scene. Absolute CC/pitch bend uses pickup (soft takeover); relative CC is optional; buttons are notes or CCs crossing 64; feedback goes back to the controller (not echoing its own value). `DeviceModel::removeEffect/moveEffect` remap effect mappings; `DeviceStore::remove/rekey` drop or rekey them. D-Bus `SetMidiController`, `StartMidiLearn(json)`, `CancelMidiLearn`, `RemoveMidiMapping`, `SetMidiMappingRelative`; GUI `MidiLearnMenu.qml` (right-click on controls) and `MidiLearnBanner.qml`. `MidiParser` (midiport.h) is shared with MackieControl; tests share `tests/fakemidiport.h`.

## Hotkeys

Hotkeys (Phase 8c): `Hotkeys` (`engine/src/hotkeys.{h,cpp}`; `Hotkey` = id + `HotkeyMode` (toggle, pushToTalk, pushToMute, duck, levelUp, levelDown) + `MidiTarget`; devices.json `hotkeys`) on a `ShortcutBackend`. The daemon's backend is `KGlobalAccelShortcuts` (`daemon/globalshortcuts.{h,cpp}`): kglobalaccel over D-Bus without QtGui (component "patchprime", doRegister + setShortcut flags SetPresent(2)/NoAutoloading(4), keys as Qt key combinations, pressed/repeated/released signals on /component/patchprime, re-registers when kglobalaccel restarts, setInactive on exit). kglobalaccel keeps the keys. `MixerTargets` (`mixertargets.{h,cpp}`) holds what MIDI and hotkeys do to targets. D-Bus `AddHotkey`, `RemoveHotkey`, `SetHotkeyKey`, `DescribeTarget`. GUI `HotkeyDialog.qml` (KQuickControls `KeySequenceItem`, needs qml6-module-org-kde-kquickcontrols / kf6-kdeclarative / kdeclarative). `test_globalshortcuts` uses the session's kglobalaccel with its own component and Ctrl+Alt+Shift+Meta+F35, removed afterwards (skips without kglobalaccel).

## patchprime-ctl

`patchprime-ctl` (Phase 8d, `ctl/`): a D-Bus client for scripts and Stream Deck. `ctl.{h,cpp}` (`patchprime-ctl-plan`) turns a command line plus GetState's JSON into D-Bus calls or text (`pp::ctl::plan`, tested by `tests/test_ctl.cpp` without a daemon); `main.cpp` calls them. Strips by label (any case), key or node name, in mixer order.

## App strips

App strips (Phase 9a): `AppMixer` (`engine/src/appmixer.{h,cpp}`) sets an app's level and mute on its streams' own Props (`PipeWireGraph::setNodeVolume`; what Plasma's applet shows, and WirePlumber restores per app), and follows changes: `PipeWireGraph` subscribes to SPA_PARAM_Props on `Stream/*` nodes (`nodeVolume`, `nodeVolumeChanged`). Meters capture straight from each stream (`addMeter(<object.serial>, channels, false)`), only while levels are watched; Levels key `app|<app key>`. `AppRouter::streamNodes`, `setHidden` (`AppSettings::hidden`, apps.json). D-Bus `SetAppVolume`, `SetAppMuted`, `SetAppHidden`; state per app `volumeDb`, `muted`, `hidden`. GUI `AppStripGroup.qml`/`AppStrip.qml` (a Repeater over app keys, reassigned only when the key list changes, so drags survive state updates); clicking the APPS heading collapses them into one column of `AppCompactRow.qml` rows (`[Mixer] appsCollapsed` in patchprime.conf).

## Tray icon and on-screen messages

Tray and OSD (Phase 9b): `patchprime-tray` (`tray/`, Qt Widgets + KF6::StatusNotifierItem; optional unless `-DPATCHPRIME_REQUIRE_TRAY=ON`, which the package builds set), a D-Bus client like the app; autostarted from `/etc/xdg/autostart/org.kingsqueak.patchprime.tray.desktop`, quits when `trayIcon` is off; single instance by the name `org.kingsqueak.PatchPrime.Tray`. Its mic = the input strip that's the default input, else the first hardware input (`Tray::micOf`). KSNI registers on its own D-Bus connection. The app is single-instance too (`app/src/windowservice.*`, `org.kingsqueak.PatchPrime.Window` /Window `Activate`; not in screenshot mode). OSD: `MixerTargets::setFeedback` (toggles), `Hotkeys`/`MidiMapper::feedback` signals, daemon `osd::showText` (plasmashell /org/kde/osdService, no autostart) when `showOsd`. Settings `trayIcon`, `showOsd` in devices.json; D-Bus `SetTrayIcon`, `SetShowOsd`. Build needs `libkf6statusnotifieritem-dev` (Fedora `kf6-kstatusnotifieritem-devel`, Arch `kstatusnotifieritem`).

## Soundboard

Soundboard (Phase 9c): `Soundboard` (`engine/src/soundboard.{h,cpp}`; `SoundPad` in `soundpad.{h,cpp}`, devices.json `pads` + `soundboardTarget`). Each playing pad is a `Player` stream `patchprime.pad.<id8>` (file rate, `Player::setGain`), linked into the target strip by `BusManager::setPadStreams` → `linkStreamInto` (shared with the recordings player). Toggle per press, overlap allowed (max 16), loop option; the first pad defaults the target to the first mix bus. MIDI/hotkey target `pad` (`MidiTarget::pad`, `MixerTargets::setPadHandlers`; removing a pad drops its mappings and hotkeys). D-Bus `AddPad`, `RemovePad`, `UpdatePad`, `MovePad`, `TriggerPad`, `StopAllPads`, `SetSoundboardTarget`; state `pads`, `soundboardTarget`, `soundboardError`; Levels `pad|<id>` = [seconds, length]. GUI `SoundboardPage.qml` (QtQuick.Dialogs FileDialog), `SoundboardPanel.qml` (mixer column), `PadButton.qml`, `PadDialog.qml`; tray Soundboard submenu; `patchprime-ctl pad|pads`.

## Ducking keyed by an app

Ducking keyed by an app (Phase 9j): a ducker's `EffectSettings::key` may be an app key, `playback|<binary>` (`isPlaybackAppKey`, approuter.h). `BusManager::linkKeys` then links the output ports of every node `classifyAppStream` gives that key into the strip's key inputs (summed to mono), with no loop check (an app's playback can't come from a strip). The link sits beside WirePlumber's own link to the app's target, so the key hears the app after its own volume and mute. `DeviceModel::setEffectKey` accepts app keys whether or not the app runs. GUI: the key picker in `EffectsWindow.qml` lists strips, then playback apps from `Devices.apps`.

## Loudness for publishing

Loudness for publishing (Phase 9f): `LoudnessMeter` (`engine/src/loudnessmeter.{h,cpp}`, a `StreamIo`) K-weights the strip's channels on the realtime thread and queues one `LoudnessBlock` (mean square, true peak) per 100 ms through a `SampleRing`; `LoudnessAnalysis` (pure, unit tested against EBU Tech 3341/3342 cases in `tests/test_loudness.cpp`) gives momentary, short-term, integrated (gated -70 / -10 LU), LRA (-70 / -20 LU, 10th–95th percentile) and true peak. `TruePeakDetector` (loudness.h) is BS.1770-4 Annex 2's 4x interpolator, about 6 samples late; the limiter's `truePeak` switch uses it (its lookahead grew by those 6 samples, in both modes). `LoudnessManager` (`loudnessmanager.{h,cpp}`) runs the capture stream `patchprime.loudness` on the strip in devices.json `loudnessStrip` (targets `loudnessTarget`, `loudnessPeakTarget`), linked by `BusManager::setLoudnessTap` like a processed recorder track, and resets when that strip starts recording. D-Bus `SetLoudnessStrip`, `SetLoudnessTarget`, `ResetLoudness`; state `loudnessStrip`, `loudnessMeasuring`, `loudnessTarget`, `loudnessPeakTarget`, `loudnessNow`; Levels `loudness`; GUI `LoudnessPanel.qml`; `patchprime-ctl loudness`.

## Presets

Presets (Phase 9d): `PresetStore` (`engine/src/presets.{h,cpp}`, `~/.config/patchprime/presets.json`: `chains` {name: effects JSON}, `effects` {type: {name: effect}}; effect presets drop bypass and ducker key). `DeviceModel::setEffects` (replaces a chain, keeps effect mappings/hotkeys where the type at that index is unchanged) and `loadEffectPreset` (params + state, same type only). D-Bus `Save/Load/DeleteChainPreset`, `Save/Load/DeleteEffectPreset`; state `chainPresets`, `effectPresets`. Saves (scenes too) go through `PatchPrimeService::afterPluginStates`: with plugin windows open, `requestPluginStates` and capture 400 ms later. GUI `PresetButton.qml` in the effects window's header (chains) and on each effect card.

## Translations

Translations (Phase 9m): `translations/patchprime_<lang>.ts`, built into the app and tray by `qt_add_translations` (top-level `CMakeLists.txt`, resource prefix `/i18n`), loaded for `QLocale()` by `pp::loadTranslations` (`translations/loadtranslations.h`) along with Qt's own `qtbase_*`, if installed. Add a language: a new `TS_FILES` entry, then `cmake --build <dir> --target update_translations` (run it too after changing any text; without it new strings stay English). Try one with `LANGUAGE=de`. German, Spanish and French are machine drafts (Grok), checked for placeholders and accelerators, not read by native speakers. Never build a sentence from translated fragments: give each case a whole string.

The engine's own words reach the GUI in English. `app/src/effectstrings.{h,cpp}` lists the effect names, parameters, options and voice chain names in the "Effects" context; `DaemonClient` translates `effectTypes` as they arrive and QML can call `Devices.effectWords()`. `test_effectstrings` fails when the engine has a word the list lacks. Still English: what the daemon writes itself (errors, MIDI and hotkey descriptions, OSD text), `patchprime-ctl`, and the user guide.

## Accessibility and keyboard

Accessibility (Phase 9m): every control has a name that says which strip it's on (`StripToggle.accessibleName`, `VolumeFader.accessibleName`). `PATCHPRIME_A11Y_DUMP=<file>` (with `PATCHPRIME_SCREENSHOT`) lists what a screen reader finds, unnamed controls marked `NO NAME`; the remaining ones are read-only text. Keyboard: `VolumeFader` takes arrows (1 dB), Page Up/Down (6 dB), Home (0 dB), End (off); Enter on a strip's fader types a level; `ChannelStrip` takes M and C from whatever has focus on it (text fields eat them first); `MixerPage` scrolls the focused control into view. Custom controls show focus with `Kirigami.Theme.focusColor` on `visualFocus`. Not tested with a real screen reader. The EQ and multiband graphs are mouse-only; their tables and parameter rows do the same from the keyboard.

## Setup wizard

Setup wizard (Phase 9m): `SetupWizard.qml` collects answers and changes nothing until Finish, which is one D-Bus call, `ApplyQuickSetup(mic, output, desktopName, streamName)`, → `DeviceModel::applyQuickSetup` (only adds; reuses strips of that kind and label, so it can be run twice) and the default input and output. Names come from the GUI so they're in the user's language. The mic is never sent to the output. It offers itself once (`[Setup] wizardSeen` in patchprime.conf) 1.5 s after connecting, if nothing's in the mixer; Help → Setup Wizard… runs it any time. `PATCHPRIME_PAGE=wizard<n>` opens step n.

## Mini window

Mini window (Phase 9m): `MiniWindow.qml`, a window of its own rather than a state of the main one (Kirigami's page stack and menu bar don't shrink to a strip's width), with one `MiniRow.qml` per strip and running app. `Main.setMini` swaps the two (the outgoing window hides only once the other is active: hidden any sooner, KWin gives the focus to another app and then refuses it to ours as focus stealing, so the new window opens behind that app; an Xvfb test with nothing else on the desktop can't show this; Ctrl+M is one toggle in Main: Qt treats a second Ctrl+M in the mini window as ambiguous, even with Main hidden); anything else that shows the main window (a second start, the tray) ends mini mode through `onVisibleChanged`. `Main` starts `visible: false` and shows itself from `Component.onCompleted`, so it doesn't flash when mini was in use. `[MainWindow] mini` and `[MiniWindow] height, onTop` in patchprime.conf; the height follows the rows until the user resizes it. `PATCHPRIME_PAGE=mini` shows both, saving the mini one as `<file>-2.png`.
