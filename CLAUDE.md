# Patch Prime

A virtual audio mixer and router for KDE Plasma on PipeWire (Linux).

## Read first
- Plan and phases: `~/obsidian/Projects/Patch Prime/Patch Prime - Plan.md`
- Architecture: `~/obsidian/Projects/Patch Prime/Patch Prime - Architecture.md`
- Session log: `~/obsidian/Projects/Patch Prime/Patch Prime - Session Log.md` (add an entry at the end of each session)

## Stack
C++23 (for `std::expected` and `std::print`), CMake + Ninja, Qt 6.10 (QML + Kirigami), KF6 6.24, libpipewire-0.3 (PipeWire 1.6, WirePlumber 0.5). Ubuntu 26.04, Plasma 6.6.

## Ground rules
- The engine runs in a daemon (`patchprimed`, a systemd user service). The GUI is a D-Bus client and contains no realtime audio code.
- Never save PipeWire numeric IDs. Key everything by `media.class` + `node.name` / `device.name`.
- Every node Patch Prime creates is named `patchprime.*` and has `node.autoconnect=false`.
- Leave `node.description` and the hardware device volume alone. Labels and levels belong to the app.
- License: GPL-3.0-or-later. Every source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later` and `// SPDX-FileCopyrightText: 2026 KC2RGW Chris`. Third-party code must be GPL-3-compatible.
- Build with GCC and Clang. Delegate self-contained tasks (reviews, research, boilerplate) to Grok: `grok -p "..." --always-approve`.

## Build
- `cmake --preset gcc-debug && cmake --build --preset gcc-debug && ctest --preset gcc-debug` (also `clang-debug`; `clang-tidy` runs clang-tidy during the build). The presets turn on `-Werror`.
- Layout: `engine/` (static library, Qt Core only, owns all libpipewire code), `probe/` (`patchprime-probe`), `ctl/` (`patchprime-ctl`), `app/` (Kirigami GUI), `tests/` (Qt Test; `test_graphsnapshot` needs a running PipeWire server and skips without one).
- Processes: `patchprimed` (`daemon/`) hosts the engine: `PipeWireGraph` (pw_thread_loop, events posted to the main thread) → `DeviceModel` (+ `DeviceStore`, `~/.config/patchprime/devices.json`) → `BusManager` (one lingering `patchprime.bus.<in|out>.<busId>` null sink per enabled device, linked to its hardware; fader/mute = the bus's channelVolumes/mute). D-Bus: `org.kingsqueak.PatchPrime` `/org/kingsqueak/PatchPrime` `org.kingsqueak.PatchPrime1` (see `daemon/service.h`). The GUI (`app/`) is only a D-Bus client (`DaemonClient`) and doesn't link the engine.
- Audio setup: `AudioSetup` applies the mixer rate/block size to PipeWire's `settings` metadata, and writes per-device rules (scheduling, own rate) to `~/.config/wireplumber/wireplumber.conf.d/60-patchprime.conf`, restarting WirePlumber when that file changes. Pro-audio interfaces that follow another clock need timer scheduling, or they xrun and pulse.
- Installed (2026-10-31) from the **.deb package** into `/usr` (`dpkg -l patchprime`; the package's postinst enables `patchprimed.service` for every user via `systemctl --global`). The old `~/.local` install was retired (files kept in `build/local-install-backup/`); don't reinstall there, its unit and D-Bus file would shadow the package's. Version: `project(VERSION)` in `CMakeLists.txt` (the display name and every title bar show it). Packages: `.github/workflows/packages.yml` builds `patchprime_<version>-1_<arch>.deb` for Ubuntu 26.04 (amd64, arm64), `.rpm` for Fedora 44 (x86_64, aarch64, user unit in `/usr/lib/systemd/user`) and an Arch package from `packaging/arch/PKGBUILD` (x86_64; keep its `pkgver` and the tarball's sha256 in step with each release), each in its distribution's container (`gh workflow run packages.yml`; a `v*` tag also attaches them to that release); `cmake/Packaging.cmake` is the CPack setup. To update this machine: download the amd64 artifact (`gh run download <id> -n patchprime-ubuntu26.04-amd64`) or build one locally (`cmake -B build/deb -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_INSTALL_PREFIX=/usr && cmake --build build/deb && (cd build/deb && cpack -G DEB)`), then in a terminal tab `sudo apt install --reinstall ./<deb> && systemctl --user restart patchprimed`.
- Don't run a second engine with another `XDG_CONFIG_HOME` to get a throwaway setup: its AudioSetup still applies its (default) mixer settings to PipeWire and restarts WirePlumber, which interrupts the user's audio. Use the tests (their own owner tags) or the real settings.
- Dev loop: only one engine can own the D-Bus name, so `systemctl --user stop patchprimed` first, then run `build/gcc-debug/daemon/patchprimed` in a terminal and the app; `systemctl --user start patchprimed` afterwards. `patchprimed --remove-buses` removes every bus. The tests run their own engines next to the service (separate owner tags and app scope).
- Don't use `pkill -f` with a pattern that appears in your own command line: it kills the shell running it. Use `pgrep -x patchprimed` / `pkill -x patchprimed`.
- QML delegates: read roles through `required property var model` (`model.foo`), not one required property per role, and don't use `ListView.section`. With Qt 6.10 both showed stale data on the wrong row after a row was inserted. Never name a role after an existing Item property (`enabled`, `visible`, ...). For a control the user drags (sliders), follow the daemon by assigning `value` in a change handler (see `VolumeFader.qml`), not with `Binding { when: !pressed }`: that left the slider drawn at one value and grabbed at another.
- `PATCHPRIME_SCREENSHOT=<file.png> QT_QPA_PLATFORM=offscreen` saves the window and quits, to check the UI without a display; point `XDG_CONFIG_HOME` at a temp dir so your real settings aren't touched (copy `~/.config/kdeglobals` there to render in the user's theme, or a `/usr/share/color-schemes/*.colors` file as `kdeglobals` for another). `PATCHPRIME_WINDOW_SIZE=1500x860` sizes the window, `PATCHPRIME_SCREENSHOT_DELAY=<ms>` waits longer (meters settle). `PATCHPRIME_PAGE=devices|routing|apps|recordings|guide` opens a page (or the user guide's window, saved as `<file>-2.png`; `about` doesn't render offscreen: run the app under `xvfb-run` and open Help → About with `xdotool` clicks, then `xwd -root`); add `QT_QPA_PLATFORMTHEME=kde` for the Plasma palette (offscreen without it, the guide's Markdown links are dark blue). The user guide is compiled into the app (Help menu, F1). The README screenshot is `docs/images/mixer.png`; the user guide is `docs/HELP.md` (keep it in step with the app).
- Recording: `engine/src/recording.{h,cpp}` (`SampleRing` lock-free SPSC queue, `Recorder` and `Player` on libsndfile: FLAC/WAV/MP3, a file thread each, the realtime side only queues) and `recordingmanager.{h,cpp}` (`patchprime.record.<bus>` capture streams on mix buses and routed inputs, one `patchprime.player` stream; `PipeWireGraph::addStream`; BusManager links them via `setTaps`, by `patchprime.tap.owner`). Files in `~/Music/Patch Prime`; format and player target saved in `devices.json`. Build needs `libsndfile1-dev` (Fedora `libsndfile-devel`, Arch `libsndfile`).
- Control surface (Phase 8a): `AlsaMidi` (`engine/src/alsamidi.{h,cpp}`, ALSA sequencer client "Patch Prime", port "Control Surface", on the main thread via QSocketNotifier; controllers named `<client>:<port>`, reconnected on announce events) implements `MidiPort`; `MackieControl` (`mackiecontrol.{h,cpp}`) is the Mackie Control protocol over any `MidiPort` (8 strips = enabled strips in mixer order, bank/channel, fader law `mackieFaderDb`, touch suppresses motor echo, V-Pots = sends to the SELECTed bus/output, display diffs, meters from `BusManager::loudness()`, F1–F8 = scenes, host-connection challenge answered). The port id is `controlSurface` in devices.json; D-Bus `SetControlSurface`, state `controlSurface*`. `tests/test_mackie.cpp` uses a `FakePort` and a stand-in ALSA client (skips without `/dev/snd/seq`). Build needs `libasound2-dev` (Fedora `alsa-lib-devel`, Arch `alsa-lib`).
- MIDI learn (Phase 8b): a second `AlsaMidi` port, "MIDI Controller", feeds `MidiMapper` (`engine/src/midimapper.{h,cpp}`); mappings are `MidiMapping`/`MidiTarget` (`midimapping.{h,cpp}`, JSON in devices.json `midiMappings`, plus `midiController`). Targets: volume, mute, cue, sendLevel, send, effectParam, effectEnabled, record, scene. Absolute CC/pitch bend uses pickup (soft takeover); relative CC is optional; buttons are notes or CCs crossing 64; feedback goes back to the controller (not echoing its own value). `DeviceModel::removeEffect/moveEffect` remap effect mappings; `DeviceStore::remove/rekey` drop or rekey them. D-Bus `SetMidiController`, `StartMidiLearn(json)`, `CancelMidiLearn`, `RemoveMidiMapping`, `SetMidiMappingRelative`; GUI `MidiLearnMenu.qml` (right-click on controls) and `MidiLearnBanner.qml`. `MidiParser` (midiport.h) is shared with MackieControl; tests share `tests/fakemidiport.h`.
- `patchprime-ctl` (Phase 8d, `ctl/`): a D-Bus client for scripts and Stream Deck. `ctl.{h,cpp}` (`patchprime-ctl-plan`) turns a command line plus GetState's JSON into D-Bus calls or text (`pp::ctl::plan`, tested by `tests/test_ctl.cpp` without a daemon); `main.cpp` calls them. Strips by label (any case), key or node name, in mixer order.
- Hotkeys (Phase 8c): `Hotkeys` (`engine/src/hotkeys.{h,cpp}`; `Hotkey` = id + `HotkeyMode` (toggle, pushToTalk, pushToMute, duck, levelUp, levelDown) + `MidiTarget`; devices.json `hotkeys`) on a `ShortcutBackend`. The daemon's backend is `KGlobalAccelShortcuts` (`daemon/globalshortcuts.{h,cpp}`): kglobalaccel over D-Bus without QtGui (component "patchprime", doRegister + setShortcut flags SetPresent(2)/NoAutoloading(4), keys as Qt key combinations, pressed/repeated/released signals on /component/patchprime, re-registers when kglobalaccel restarts, setInactive on exit). kglobalaccel keeps the keys. `MixerTargets` (`mixertargets.{h,cpp}`) holds what MIDI and hotkeys do to targets. D-Bus `AddHotkey`, `RemoveHotkey`, `SetHotkeyKey`, `DescribeTarget`. GUI `HotkeyDialog.qml` (KQuickControls `KeySequenceItem`, needs qml6-module-org-kde-kquickcontrols / kf6-kdeclarative / kdeclarative). `test_globalshortcuts` uses the session's kglobalaccel with its own component and Ctrl+Alt+Shift+Meta+F35, removed afterwards (skips without kglobalaccel).
- Plugins (Phase 7a, LV2): an effect of type `lv2:<uri>` (params by port symbol) in the same chain as the built-ins. `splitChain` cuts a strip's chain into segments: runs of built-ins run in `patchprime.fx.<rest>[.<n>]` filters in the engine, each plugin in its own `patchprime-pluginhost` process (`pluginhost/`, the only code linking lilv; installed to libexecdir) as node `patchprime.plug.<rest>.<n>`. BusManager links the segments in series and skips ones that aren't up (crash bypass); `PluginRunner` (engine) starts/restarts hosts and talks JSON lines over stdin/stdout (host exits on stdin EOF; exit code 2 = can't load). `PluginCatalog` runs `patchprime-pluginhost --scan` only when asked (Scan Plugins, D-Bus `RescanPlugins`) or when the cache (`~/.cache/patchprime/plugins.json`, `{version, scannedAt, plugins}`) is missing or another `cacheVersion` (bump it when the list's format changes); the scan prints `{"progress": {done, total, found}}` lines, then the list. `pluginHostProgram()` prefers the build tree's host (`$PATCHPRIME_PLUGINHOST` overrides). Plugin windows (7b): the host opens the plugin's X11UI itself (`pluginhost/lv2ui.{h,cpp}`, plain Xlib top-level, no suil; needs DISPLAY in the systemd user env), idles it at 30 Hz, sends control/meter values and atom events (`EventRing`); UI control changes come back as `{"param"}` and are saved via DeviceModel; the plugin's own state (`EffectSettings::state`, lilv state string, no port values) comes back as `{"state"}` on window close / every 5 s while open / `requestPluginStates()`, and is restored before activation (`--state-follows`). CLAP (7c): type `clap:<id>`, params by CLAP param id (decimal); SDK headers fetched by `cmake/Clap.cmake` (1.2.10, SHA-256 pinned; target `patchprime-clap`); `pluginhost/clap.{h,cpp}` (`ClapEffect`, `ClapWindow`, scan via `--scan-clap <file>` subprocesses since CLAP plugins must be loaded to be read); `HostedPlugin`/`PluginWindow` (`pluginhost/hostedplugin.h`) let main.cpp run either format; `X11Window` is shared. The catalog keeps each CLAP plugin's `.clap` path (`binary`). Params reach a CLAP plugin only while it processes (an unlinked node shows stale values in its window). Tests also use `tests/clap/testgain.c` via `PATCHPRIME_CLAP_PATH` (replaces the CLAP search path). VST3 (7d): type `vst3:<class id hex>`, params by ParamID (decimal; stepped ≤31 store the step index, others normalized 0–1); only `vst3_pluginterfaces` v3.8.0 (MIT) is fetched by `cmake/Vst3.cmake` (target `patchprime-vst3`, interface IIDs in `pluginhost/vst3iids.cpp`); host classes in `pluginhost/vst3.cpp` with `U::Implements`; bundles scanned by `--scan-vst3 <bundle>` subprocesses (4 at a time; the scan doesn't create editor views, too slow for LSP); search path replaced by `PATCHPRIME_VST3_PATH` in tests (`tests/vst3/testgain.cpp`, component = controller). Tests use `tests/lv2/testgain.c` (gain, a "crash" switch, a "halve" switch kept only in its state) via `LV2_PATH`; never rely on installed plugins in tests. Build needs `liblilv-dev lv2-dev libx11-dev` (Fedora `lilv-devel lv2-devel libX11-devel`, Arch `lilv lv2 libx11`).
- Effects: `engine/src/` `effects`, `eq`, `multiband`, `dynamics`, `denoise` form `patchprime-dsp` (plain C++, linked by the engine and the GUI, which draws curves with it). RNNoise is fetched at configure time (`cmake/RNNoise.cmake`, pinned by SHA-256; `-DPATCHPRIME_RNNOISE=OFF` builds without noise suppression). `PATCHPRIME_EFFECTS=<strip label>` opens a strip's effects window for screenshots (saved as `<file>-2.png`).
- QML: never give an id or property an existing Item/Layout property name (`scale`, `spacing`, ...): it is shadowed or "set multiple times".
- Kirigami is used only from QML. Don't `find_package(KF6Kirigami)`: its CMake config needs OpenMP, which Clang builds here lack.
